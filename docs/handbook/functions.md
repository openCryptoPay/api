# Functions

## Function: normalizePlaceOrigin

- **Purpose:** Trim a pin origin and accept only `^[a-z0-9][a-z0-9-]{0,31}$`. A leading digit is valid. Uppercase tokens such as SPAR are invalid.
- **Inputs:** Unknown value, typically a JSON field or the `origin` query string.
- **Returns / side effects:** `{ ok: true, value }` with the trimmed origin, or `{ ok: false, error: "Place origin is invalid" }`. No I/O.
- **Used by:** `normalizeMapPlace`, `normalizeMapPlaceKey`, `normalizePhotoUpload`, `mapRoutes` on `GET /map/places`, and `adminRoutes` when an internal-id body includes `origin`.

## Function: normalizeExternalId

- **Purpose:** Trim a caller id and accept only a string of 1 to 80 characters with no character code below 32 and no DEL (127). A non-string, a blank trim, a longer value, or a control character is rejected.
- **Inputs:** Unknown value, typically a JSON `externalId`.
- **Returns / side effects:** `{ ok: true, value }` with the trimmed caller id, or `{ ok: false, error: "Place external id is required" }`. No I/O.
- **Used by:** `normalizeMapPlace`, `normalizeMapPlaceKey`, and `adminRoutes` when an internal-id body includes `externalId`.

## Function: normalizeMapPlace

- **Purpose:** Validate a JSON body for one map pin. The body must be a JSON object whose keys are exactly origin, externalId, name, description, lat, lon, category, paymentMethods, techProvider, shopType, street, houseNumber, postalCode, city, country, supports, nostrPubkey, googleMapsUrl, and revision. The first unknown key in `Object.keys` order, including the old `shopName`, is `Place field is not allowed: <key>` with `<key>` cut to its first 40 characters. Coordinates must be finite and in range, then they are rounded to six decimals. An unknown payment list becomes null instead of an error. An omitted tech provider is left unset so the store can default it. An omitted `supports` list is `[]`. Country is required, trimmed, and uppercased as an assigned ISO 3166-1 alpha-2 code. Street is required, trimmed, 1 to 120 characters, without control characters. House number is required, trimmed, and must match `^[0-9][0-9A-Za-z/ .&–-]{0,31}$`. Postal code is required and trimmed: CH and LI must be exactly four digits, other countries `^[A-Za-z0-9][A-Za-z0-9 -]{1,15}$`. City is required, trimmed, 1 to 80 characters, without control characters, and must contain a letter. Name is required, trimmed, 1 to 80 characters, without control characters. The name may contain the street. It must not contain the postal code as a standalone token. Description normalises `\r\n` and lone `\r` to `\n` before any check and is then trimmed. It must be 20 to 1000 characters, may contain newlines but no other control characters, and must be longer than the trimmed name and not equal to it case-insensitively. Shop type is required and exactly `SPAR` or `Others`. `nostrPubkey` (R7) is required (step 1b of `docs/product/shop-identity.md`): a missing key is `Place NOSTR public key is required`, a key that fails `isNostrPubkey` is `Place NOSTR public key is invalid`, and it is stored as given, never derived. `revision` (R8) is optional; when present it must be an integer from 1 to 9007199254740991, otherwise `Place revision is invalid`. A missing `googleMapsUrl` key leaves the property unset. JSON null is `googleMapsUrl: null`. Any other value that `isGoogleMapsUrl` rejects is `Place Google Maps link is invalid`. A valid link is stored trimmed. No stored field is derived from another field.
- **Inputs:** Unknown JSON. Required fields are `origin`, `externalId`, `name`, `description`, `lat`, `lon`, `category`, `shopType`, `street`, `houseNumber`, `postalCode`, `city`, and `country`. `nostrPubkey` is required. `techProvider`, `supports`, `revision`, and `googleMapsUrl` may be omitted. A present `googleMapsUrl` is null or a trimmed link.
- **Returns / side effects:** `{ ok: true, value, revision }` with `value.nostrPubkey` always set and `revision` beside the pin (undefined when omitted), or `{ ok: false, error }` with a fixed English message. First failure wins. No I/O.
- **Used by:** `mapRoutes` on `POST /map/places`, `putPlace` on `PUT /map/places` and on `PUT /admin/places` when the body has no own property `id`, and `adminRoutes` on an internal-id replace after `id`, `createdAt`, `lastTransactionAt`, and `activity` are removed (a `revision` is rejected before) and the resolved origin and caller id are set.

## Function: normalizeMapPlaceFilter

- **Purpose:** Validate the optional `country`, `shopType`, deprecated `shopName`, `blockchain`, and `asset` query strings for the public map. Omitted parameters stay off the filter. Unknown query parameters stay ignored. `country` is trimmed and uppercased. `shopType` is trimmed and must be `SPAR` or `Others`. The deprecated `shopName` query maps `SPAR` to `SPAR` and `others` to `Others` for one release and is removed in the release after the rollout. If both `shopType` and `shopName` are present and map to different types, the result is `Place shop type is invalid`. `blockchain` and `asset` are trimmed and not casefolded. A filter blockchain may be a stored payment-network name or a payment-link network such as BinancePay or KucoinPay. A filter asset may be a ticker, a prefixed ticker, or a catalog name such as ckBTC or dEURO. A support body still uses the stricter stored-pair rules.
- **Inputs:** Five optional raw query strings: country, shopType, legacy shopName, blockchain, and asset.
- **Returns / side effects:** `{ ok: true, value }` with the present filter fields, or `{ ok: false, error }` with `Place country is invalid`, `Place shop type is invalid`, `Place shop name is invalid`, or `Place support is invalid`. No I/O.
- **Used by:** `mapRoutes` on `GET /map/places` and `GET /map/filters`.

## Function: isCatalogBlockchain

- **Purpose:** Report whether a trimmed blockchain query is in the hardcoded payment-link catalog. Test networks, Plasma, and names that are not payment-link networks are excluded. BinancePay and KucoinPay are included.
- **Inputs:** A trimmed blockchain string.
- **Returns / side effects:** True or false. No I/O.
- **Used by:** `normalizeMapPlaceFilter` when a blockchain query is not a stored payment-network name.

## Function: isCatalogAsset

- **Purpose:** Report whether a trimmed asset query is in the hardcoded payment-link catalog. This includes names that are not plain tickers, such as ckBTC and dEURO.
- **Inputs:** A trimmed asset string.
- **Returns / side effects:** True or false. No I/O.
- **Used by:** `normalizeMapPlaceFilter` when an asset query is not a ticker or a prefixed ticker.

## Function: matchesUnstatedPayment

- **Purpose:** Decide whether a tech provider's offer includes a blockchain or asset filter. `21.gifts` matches Lightning/BTC, Spark/BTC, and its USDT and USDC pairs, including a chain or asset that appears in one of those pairs. `DFX.swiss` matches a chain from its pairs, a catalog asset, or a catalog pair. Gnosis and Zano stay catalog networks and do not match, because they have no pair. Any other provider matches none. Origin is not an input. An omitted filter matches.
- **Inputs:** Stored tech provider, and the optional blockchain and asset from the query.
- **Returns / side effects:** True when the pin stays in the list. No I/O.
- **Used by:** `MemoryMapPlaceStore.list`. The SQLite driver uses `unstatedPaymentSql` for the same rule.

## Function: unstatedPaymentSql

- **Purpose:** Build the SQLite predicate for a blockchain or asset filter from `tech_provider` alone. `21.gifts` matches Lightning/BTC, Spark/BTC, and its USDT and USDC pairs. `DFX.swiss` matches the DFX catalog. A request outside both offers matches no pin. Origin and stored support rows are not part of the predicate. No network and no asset returns null.
- **Inputs:** Optional blockchain and asset query values.
- **Returns / side effects:** A parenthesised SQL fragment and its bound parameters, or null. No I/O.
- **Used by:** `SqliteMapPlaceStore.list`.

## Function: publicFilterResponse

- **Purpose:** Build the `GET /map/filters` lists from the two tech-provider offers. Stored support rows are not included. Countries stay the stored public countries. `shopTypes` is always `["SPAR", "Others"]`. `shopNames` is the deprecated one-release alias `["SPAR", "others"]` and is removed in the release after the rollout. `?blockchain=` limits the top-level asset list. `techProviders` always contains the full `DFX.swiss` offer and the `21.gifts` offer of Lightning/BTC, Spark/BTC, and its USDT and USDC pairs.
- **Inputs:** Stored countries, plus an optional blockchain query. Stored blockchains and assets are ignored.
- **Returns / side effects:** `{ shopTypes, shopNames, countries, blockchains, assets, activities, techProviders }`. `activities` is always `daily`, `within7Days`, `within30Days`, `olderThan30Days`, `none`, including when `?blockchain=` limits the asset list. No I/O.
- **Used by:** `mapRoutes` on `GET /map/filters`.

## Function: publicPlaceSupports

- **Purpose:** Return the public support pairs of one pin from its tech provider alone. `DFX.swiss` is the DFX catalog, including ZCHF on Ethereum and Polygon. `21.gifts` is Lightning/BTC, Spark/BTC, and every USDT and USDC pair from Flashnet Orchestra. Any other provider is an empty list. Origin and stored support rows are not inputs.
- **Inputs:** The stored tech provider.
- **Returns / side effects:** A new array of `{ blockchain, asset }`. Mutating it does not change the next call. No I/O.
- **Used by:** `toPublicMapPlace`.

## Function: normalizeMapPlaceKey

- **Purpose:** Validate origin and external id of a pin. An own property `id` is rejected with `Place field is not allowed: id` before origin and external id are checked. Other extra JSON fields are ignored. The body does not need coordinates or a name.
- **Inputs:** Unknown JSON. Required fields are `origin` and `externalId`, with the same rules as `normalizeMapPlace`.
- **Returns / side effects:** `{ ok: true, value: { origin, externalId } }` or `{ ok: false, error }` with the same English messages as create. No I/O.
- **Used by:** `normalizePlaceTransaction` and `normalizeMapPlaceDelete`.

## Function: normalizeMapPlaceDelete

- **Purpose:** Validate a `DELETE /map/places` body. Allowed keys are exactly `origin`, `externalId`, and `revision` (R8); the first other key in `Object.keys` order is `Place field is not allowed: <key>` with `<key>` cut to 40 characters. `origin` and `externalId` use `normalizeMapPlaceKey`. `revision` is optional; when present it must be an integer from 1 to 9007199254740991, otherwise `Place revision is invalid`. `POST /map/places/transactions` keeps `normalizeMapPlaceKey`, which ignores other keys.
- **Inputs:** Unknown JSON. Null, an array, and a non-object are `Place origin is invalid`.
- **Returns / side effects:** `{ ok: true, value: { origin, externalId }, revision }` or `{ ok: false, error }`. No I/O.
- **Used by:** `deletePlace`, shared by `mapRoutes` and the no-id path of `adminRoutes`. An internal-id admin body does not call this function.

## Function: isNostrPubkey

- **Purpose:** Check a NIP-01 public key (R7): exactly 64 lowercase hex characters naming the x coordinate of a point on secp256k1. The x value must be below the field prime and `x³ + 7` must be a square modulo that prime (Euler's criterion). An `npub`, uppercase hex, and any other form are rejected.
- **Inputs:** Any JSON value.
- **Returns / side effects:** True or false. No I/O.
- **Used by:** `normalizeMapPlace`, `normalizePhotoUpload`, and `mapRoutes` on `GET /map/places/:id` for the hex form.

## Function: isGoogleMapsUrl

- **Purpose:** Decide whether a trimmed string is a Google Maps https link that a place write may store. The string is at most 2000 characters, has no whitespace, no backslash, and no control or format character (Unicode `Cc` or `Cf`, such as NUL, DEL, or a zero-width space), uses `https`, has the host directly after `https://` (no extra slash), and has no userinfo and no port. The host is exactly `www.google.com`, `google.com`, `maps.google.com`, or `maps.app.goo.gl`. Scheme and host match without regard to case, as the URL parser lowercases them; the link is stored as sent. The first three need the path `/maps` or a path that starts with `/maps/`. `maps.app.goo.gl` needs a path longer than `/`. Query and hash stay. The caller trims; this check does not.
- **Inputs:** A trimmed string.
- **Returns / side effects:** True or false. No I/O.
- **Used by:** `normalizeMapPlace` and `SqliteMapPlaceStore` when it seeds links on the open that adds `google_maps_url`.

## Function: npubEncode

- **Purpose:** NIP-19 `npub` (bech32, prefix `npub`) of a public key. The npub is never stored; it is computed wherever a shop id is shown.
- **Inputs:** A key accepted by `isNostrPubkey`.
- **Returns / side effects:** The 63-character `npub1…` string. No I/O.
- **Used by:** `toPublicMapPlace`, `putPlace`, `adminRoutes` for the `npub` of an internal-id `PUT`, and `mapRoutes` on `POST /map/places` and for the redirect of `GET /map/places/:id`.

## Function: npubDecode

- **Purpose:** Public key named by an `npub`. The string must be lowercase `npub1` plus 58 bech32 characters with a valid checksum and zero padding bits.
- **Inputs:** A path segment or any string.
- **Returns / side effects:** 64 lowercase hex characters, or null. No I/O.
- **Used by:** `mapRoutes` on `GET /map/places/:id`.

## Function: placeWriteConflict

- **Purpose:** Decide whether a place write is refused, in the order R8 and R7 fix. First the revision: once a revision is stored for the origin and external id, a write without one, or with one that is not higher, is `Stale revision`. Then the key, only when the write carries one: a row that already has a key refuses a different key with `nostrPubkey of a place cannot change`; otherwise a key reserved for another origin or external id is `nostrPubkey belongs to another place`. So when both key rules break, the stored key decides.
- **Inputs:** The stored revision, the sent revision, whether the pair has a row and that row's key, the sent key, the pair the sent key is reserved for, and the pair of the write.
- **Returns / side effects:** The 409 text, or null when the write may go ahead. No I/O.
- **Used by:** `MemoryMapPlaceStore` and `SqliteMapPlaceStore` inside `insertIfNew` and `upsert`, and without revisions inside `replaceById`, before anything is stored.

## Function: placeNameConflict

- **Purpose:** Decide whether a place write that stores a name is refused because another row already stores that exact name. `ownerId` null, or `ownerId` equal to `selfId`, allows the write. Any other `ownerId` is `Place name belongs to another place`. The comparison is the caller's: this function does not trim and does not fold case, so `Shop` and `shop` are different names. It runs only after `placeWriteConflict` returned null, and only when the write stores the name.
- **Inputs:** `ownerId`, the id of a row that already stores this exact name, or null. `selfId`, the id of the row being written, or null on insert.
- **Returns / side effects:** Null when `ownerId` is null or `ownerId === selfId`. Otherwise `Place name belongs to another place`. No I/O.
- **Used by:** `MemoryMapPlaceStore` and `SqliteMapPlaceStore` inside `insertIfNew` when the origin and external id are new, inside `upsert` for a new or replacing write, and inside `replaceById`, after `placeWriteConflict` and before anything is stored.

## Function: placeActivity

- **Purpose:** Classify a stored transaction instant and payment days into `daily`, `within7Days`, `within30Days`, `olderThan30Days`, or `none`. First match wins. `daily` is at least five distinct stored UTC dates (`YYYY-MM-DD`) that lie on the UTC date of `nowMs` or on one of the previous six UTC dates. Duplicates and strings that are not that date form or that lie outside the window are ignored. `within7Days` is a parseable instant whose age is at most `7 * 24 * 60 * 60 * 1000` ms (exactly 7 days stays here; a future instant stays here) when the row is not `daily`. `within30Days` is older than 7×24h and at most 30×24h (exactly 30 days stays here). One millisecond past 30×24h is `olderThan30Days`, not `none`. `none` is a null or unparseable instant when the row is not `daily`.
- **Inputs:** `lastTransactionAt` (`string | null`), `paymentDays` (readonly UTC date strings), and `nowMs` (maintenance clock in milliseconds).
- **Returns / side effects:** `{ activity, until }`. For `daily`, `until` is UTC midnight at the start of the fifth-newest counted day plus 7 days. For `within7Days` and `within30Days`, `until` is one millisecond after the 7-day or 30-day bound. For `olderThan30Days` and `none`, `until` is null. No I/O.
- **Used by:** `MemoryMapPlaceStore` and `SqliteMapPlaceStore` on the transaction write, when `activity_until` is due, and on `replaceById` when the activity write is `recompute`.

## Function: normalizePlaceTransaction

- **Purpose:** Validate a JSON body that records a shop transaction. `origin` and `externalId` use `normalizeMapPlaceKey` and the same error strings. Extra JSON fields other than an own property `id` are ignored. An own property `id` is `Place field is not allowed: id`, because origin and external id go through `normalizeMapPlaceKey`. Omitted `occurredAt` becomes `new Date(nowMs).toISOString()`. A present `occurredAt` must be a parseable string at most 120 seconds after `nowMs`; exactly `nowMs + 120_000` is valid and one millisecond later is not. The returned instant is canonical ISO (`new Date(parsed).toISOString()`), not the raw string. An instant whose canonical form does not start with a four-digit year, such as a negative year, is `Place transaction time is invalid`, because SQLite `julianday` cannot read it.
- **Inputs:** Unknown JSON and `nowMs`. Required fields are `origin` and `externalId`. `occurredAt` is optional.
- **Returns / side effects:** `{ ok: true, value: { origin, externalId, occurredAt } }` or `{ ok: false, error }` including `Place transaction time is invalid`. No I/O.
- **Used by:** `mapRoutes` on `POST /map/places/transactions`.

## Function: toPublicMapPlace

- **Purpose:** Strip the caller id and payment methods before a pin is shown on the public map. `id` is the shop's npub (`npubEncode` of the stored key), or null for a row without a key, which only `adminRoutes` shows; the internal UUID is not returned here. The tech provider, description, shop type, street, house number, postal code, city, country, and supports stay on the public row. `supports` is `publicPlaceSupports` of the tech provider, including when stored rows exist or are empty. `shopName` is derived for one release as `'SPAR'` when `shopType` is `'SPAR'`, otherwise null, and is removed in the release after the rollout. Address parts on a public row are strings. `activity` is copied from the stored pin. A read does not reclassify. `coverPhoto` is the first stored photo as `{ url, width, height }` with an absolute `url` from `OCP_PUBLIC_BASE_URL`, or null. `googleMapsUrl` is copied from the stored pin: the stored https link, or null. It is not part of completeness. `GET /admin/places` sets `id` to the internal id and adds `npub` (this function's `id`), `externalId`, `paymentMethods`, `createdAt`, `lastTransactionAt`, and `active` beside this result. This function does not copy `active` and omits those other admin fields. It does not add `activityUntil` or payment days.
- **Inputs:** A stored map pin and `OCP_PUBLIC_BASE_URL`. Public map callers pass a complete row; `adminRoutes` may pass an incomplete row.
- **Returns / side effects:** `id`, `origin`, `name`, `description`, `lat`, `lon`, `category`, `techProvider`, `shopType`, `shopName`, `country`, `street`, `houseNumber`, `postalCode`, `city`, `supports`, `activity`, `coverPhoto`, and `googleMapsUrl`. No I/O.
- **Used by:** `mapRoutes` on `GET /map/places`, `toPublicMapPlaceDetail`, and `adminRoutes` on `GET /admin/places`.

## Function: MemoryMapPlaceStore

- **Purpose:** In-memory map store with the same insert-once, full-replace upsert, delete, `recordTransaction`, and `refreshActivity` rules as SQLite. New rows store `lastTransactionAt` null, `activity` `none`, `activity_until` null, no payment days, and `active` true. Completeness: a row is complete when name, description, shop type (`SPAR` or `Others`), street, house number, postal code, city, and country are non-empty and `lastTransactionAt` is null or starts with a four-digit year and `Number.isFinite(Date.parse(...))`, which matches what SQLite `julianday` reads for the canonical ISO instants this service writes. `list` and the `countries` of `filters` use only public rows, which are complete and `active`. `filters` still reads blockchains and assets from every row, including inactive and incomplete rows. `listAll` and `getById` still return inactive rows. `listAll` returns every row, including incomplete rows, newest first with no filter or limit. A row is also incomplete without a NOSTR key (R7). `active` is not part of completeness. Payment days and `activity_until` stay beside the row, not on `StoredMapPlace`. Key reservations and revisions stay beside the rows too and are never removed by `deleteByKey`. `insertIfNew` and `upsert` first run `placeWriteConflict`, then `placeNameConflict` when the write stores the name. A refused write stores nothing and returns `{ ok: false, error }` (`Stale revision`, a NOSTR key text, or `Place name belongs to another place`). `insertIfNew` of an existing pair does not store the name and does not call `placeNameConflict`. `upsert` stores the name whether the pair is new or already stored. `replaceById` runs `placeWriteConflict` without revisions, then `placeNameConflict`, and returns either refusal as `keyConflict` (see below). `deleteByKey`, `replacePhotos`, and `deleteById` do not call it; `deleteByKey` and `replacePhotos` apply only the revision rule (`Stale revision`). A write that stores a key not yet reserved reserves it for its origin and external id. A write with a revision stores it, also when it changes nothing. A repeat of origin plus external id on insert returns the first row unchanged, including its tech provider, description, shop type, address, supports, last transaction instant, `activity`, `activity_until`, and payment days. The one exception is the key: a first row without a key stores the key the repeat carries. An upsert replaces the operator fields of the pin and replaces the Google Maps link only when the write carries the key. It does not write `active`, and does not clear the timestamp, `activity`, `activity_until`, or payment days; it keeps a stored key and adds a key to a row without one. A repeat insert does not write `active` and does not change the Google Maps link. An omitted tech provider becomes `DFX.swiss`. An omitted supports list becomes `[]`. No field is derived from another field. `getById` returns a copy of the row for that internal id, or undefined. It does not trim the id and does not look up by name, caller id, or key. `deleteById` removes that row with its payment days, `activity_until`, and photos, and drops files no row uses any more; it neither checks nor stores a revision, and the pair's key reservations and revision stay. An unknown id removes nothing. `replaceById` updates that one internal id and never inserts a row. A missing id returns `missing` and writes nothing. When a different row already has the new origin and caller id, it returns `conflict` and writes nothing, including supports, activity, the refresh deadline, and payment days. The same id is not a conflict. It then runs `placeWriteConflict` without revisions against the new pair: a sent key different from a stored one, or a sent key reserved for another pair, returns `keyConflict` with that text and writes nothing. It then runs `placeNameConflict`: another row with this exact name returns `keyConflict` with `Place name belongs to another place` and writes nothing. The row's own name is allowed. Otherwise it keeps a stored key or stores the sent key on a row without one, reserves the row's key for the new pair (moving its reservation), and sets origin, caller id, name, description, lat, lon, category, payment methods, tech provider (omitted becomes `DFX.swiss`), country, street, house number, postal code, city, shop type, the unique sorted supports, `createdAt`, and `lastTransactionAt`; it does not change the id, the photos, or any revision, and it always writes `active`. `keep` leaves `activity`, `activity_until`, and payment days. `set` stores that activity token, sets `activity_until` null so `refreshActivity` skips the row, and leaves payment days. `recompute` leaves payment days and sets `activity` and `activity_until` from `placeActivity` of the written last transaction instant, those days, and `nowMs`. A null last transaction is not a special case: five counted payment days are still `daily`, and no such days are `none`. The returned place is a copy.
- **Inputs:** `insertIfNew` and `upsert` take a validated pin and an optional revision. `replaceById` takes the internal id, a validated pin, `createdAt`, `lastTransactionAt` (`string | null`), an activity write (`keep`, `set` with a `PlaceActivity`, or `recompute`), a required `active` boolean that is always written, and `nowMs`. `getById` and `deleteById` take the internal id and do not trim it. `recordTransaction` takes origin, external id, an occurred-at string, and `nowMs`. `refreshActivity` takes `nowMs`. `deleteByKey` takes origin, external id, and an optional revision. `findPublicByPubkey` takes a 64-character hex key. `replacePhotos` takes origin, key, prepared photos, and an optional revision. `findPublicPhoto` takes a SHA-256 hex hash. `list` takes a positive limit and an optional filter object (`origin`, `country`, `shopType`, `blockchain`, `asset`). `listAll` takes no arguments. `filters` takes an optional blockchain.
- **Returns / side effects:** `insertIfNew` and `upsert` return `{ ok: true, created, place }` or `{ ok: false, error }` with the `placeWriteConflict` or `placeNameConflict` text. `insertIfNew` reports whether it created the row. `getById` returns a copy or undefined when the id is missing. `deleteById` is true only when that row was removed. `replaceById` returns `{ status: 'updated', place }` with a copy, `{ status: 'missing' }`, `{ status: 'conflict' }`, or `{ status: 'keyConflict', error }` (`nostrPubkey of a place cannot change`, `nostrPubkey belongs to another place`, or `Place name belongs to another place`); all but `updated` leave every row and reservation unchanged. `upsert` replaces name, description, lat, lon, category, paymentMethods, techProvider, shopType, street, houseNumber, postalCode, city, country, and supports. `recordTransaction` returns a copy or undefined when the pair is missing. An unparseable `occurredAt` does not change the row. A written instant is `new Date(newMs).toISOString()`. It does not insert, does not move an equal or newer stored instant backward, does not change `active`, and replaces a null or unparseable stored value. A parseable instant deletes stored payment days older than the 7-date window start of `nowMs` before classifying, stores its UTC date only when that date is inside that window, then stores `activity` and `activity_until` from `placeActivity`. `refreshActivity` updates only rows whose stored `activity_until` is non-null and due, deletes payment days older than the window start, and stores the new token and `until`. `deleteByKey` returns `{ ok: false, error: "Stale revision" }` when a revision is already stored for the pair and the write sends none or one that is not higher, otherwise stores the sent revision and returns `{ ok: true, deleted }`, with `deleted` true only when a row was removed; it drops that row's payment days. `findPublicByPubkey` returns a copy of the public row with that key, or undefined. `list` is newest public pins first, then id descending. `listAll` is every row, including incomplete rows, newest first, with no limit. Neither calls `refreshActivity` or joins payment days. Predicates are AND and apply before sort and limit. `shopType` matches the stored enum. A blockchain or asset filter matches the pin's tech provider only. `21.gifts` matches Lightning/BTC, Spark/BTC, and its USDT and USDC pairs. `DFX.swiss` matches the DFX catalog. Any other provider matches none. Origin and stored support rows are not filter criteria. `filters` returns distinct countries of public rows, plus blockchains and assets from every row, including inactive and incomplete rows. `replacePhotos` finds the row with that key and origin, listed or not (otherwise `Place not found`), applies the revision rule of the row's pair (`Stale revision`), stores the revision, replaces the row's photos in order, and drops every file no row uses any more. `findPublicPhoto` returns a copy of a file only while a public row uses it. `replacePhotos` still finds a shop that is not publicly listed. `deleteByKey` also drops files no row uses any more; `upsert` keeps the photos. `close` drops the rows, reservations, revisions, and photo files.
- **Used by:** Unit tests. The process uses `SqliteMapPlaceStore`.

## Function: SqliteMapPlaceStore

- **Purpose:** SQLite driver for map pins. The schema is `MAP_PLACE_SCHEMA_SQL` (`description` and `shop_type` columns, no `shop_name` on a new database). Opening an older file adds `tech_provider`, `country`, `street`, `house_number`, `postal_code`, `city`, `description`, `shop_type`, `last_transaction_at`, `activity`, `activity_until`, `nostr_pubkey`, `active`, and `google_maps_url` when those columns are missing, and creates `map_place_support`, `map_place_payment_day`, `map_pubkey_reservation`, `map_place_revision`, `map_photo`, `map_place_photo`, and their indexes if missing, including the unique index on `nostr_pubkey`, which allows several nulls. An existing leftover `shop_name` column is left in place and is never read or written. Country and shop type are not backfilled from the name or origin. Adding `active` is `ALTER TABLE map_place ADD COLUMN active INTEGER NOT NULL DEFAULT 1` when the column is missing. There is no backfill; existing rows stay 1. Adding `google_maps_url` is `ALTER TABLE map_place ADD COLUMN google_maps_url TEXT` when the column is missing, with no default, so existing rows stay null. Exactly that open writes the seed links, only where the column is null and the key matches the decoded npub, in the same transaction as that `ALTER TABLE`: when the seed fails, the column is not added and the next open tries both again. A later open does not write them again. Opening a file that lacks `activity` then backfills every existing row once from `last_transaction_at` at `Date.now()`: at most that one UTC day when it is inside the window, then `activity` and `activity_until`. It does not invent the other days. Every constructor open, including a file that already has the column, ends by calling `refreshActivity(Date.now())`. Completeness: a row is complete when name, description, shop_type in (`SPAR`, `Others`), street, house_number, postal_code, city, and country are non-null and non-empty, `nostr_pubkey` is not null (R7), and `last_transaction_at` is null or `julianday(last_transaction_at) IS NOT NULL`. `insertIfNew` and `upsert` each run in one transaction: they read the stored revision and, for a sent key, its reservation, apply `placeWriteConflict`, then when the write stores the name read `SELECT id FROM map_place WHERE name = ?` and apply `placeNameConflict` (409 `Place name belongs to another place`), then reserve a new key, store the revision, and write the row, with the same results as `MemoryMapPlaceStore`. `insertIfNew` of an existing pair does not check the name. `upsert` checks it for a new or replacing write. `deleteByKey` also runs in one transaction: it reads the stored revision, applies only the revision rule, stores a sent revision, and deletes the row; it reads and writes no key reservation. Photos live in `map_photo` (each distinct file once by hash) and `map_place_photo` (place, position 0 to 9, hash, caption); lists load them in chunks of at most 500 place ids, as supports. `replacePhotos` runs in one transaction with the same rules as the memory store and deletes every `map_photo` row no `map_place_photo` row uses; `deleteByKey` does the same after the cascade removes the place's photo rows. `findPublicPhoto` returns a file only while a public row uses it. `list`, the country query of `filters`, `findPublicByPubkey`, and `findPublicPhoto` use `PUBLIC_PLACE_SQL`, which is `COMPLETE_PLACE_SQL` and `active` = 1. Upsert does not write `active`. `replaceById` does. `listAll` returns every row, including incomplete rows, newest first with no filter or limit. An upsert is a full replace of every pin field except the Google Maps link. An upsert does not delete the link unless the write sends the key. New rows store `last_transaction_at` null, `activity` `none`, `activity_until` null, no payment days, and `active` 1. An upsert and a repeat insert do not write `active` and do not clear the timestamp, `activity`, `activity_until`, or payment days. A repeat insert does not overwrite the first row, except that a row without a key stores the key the write carries, and it does not change the Google Maps link. An insert that `placeWriteConflict` or `placeNameConflict` refuses writes nothing. `recordTransaction` and `deleteByKey` also work on incomplete rows. `getById` returns one mapped copy, or undefined when the internal id is missing; it does not look up by name. `deleteById` deletes the row by id in one transaction, so support rows, payment days, and photo rows cascade, then deletes every `map_photo` row no `map_place_photo` row uses; it neither checks nor stores a revision. An unknown id removes nothing. `replaceById` is one transaction that updates that internal id only and never inserts. A missing id writes nothing. A different row with the same origin and caller id writes nothing. It then reads the reservation of a sent key and runs `placeWriteConflict` without revisions against the new pair, then `placeNameConflict`; either refusal returns `keyConflict` (409 `Place name belongs to another place` for the name) and writes nothing. Otherwise it keeps a stored key or stores the sent one, upserts the reservation of the row's key to the new pair, and updates the row. A UNIQUE failure rolls back, including support rows, and returns `conflict`. `activity_until` is not in the selected column list and is still updated in that transaction. `keep` does not change `activity`, `activity_until`, or payment days. `set` stores the token and `activity_until` null and does not change payment days. `recompute` leaves payment days and stores `activity` and `activity_until` from `placeActivity` of the written instant, those days, and `nowMs`. A null last transaction is not a special case: five counted payment days are still `daily`, and no such days are `none`. The id column, the photos, and the revisions are not written. Every replace writes `active` as 1 or 0.
- **Inputs:** Constructor takes a SQLite filename or `:memory:`. `replaceById` takes the same id, validated pin, timestamps, activity write, required `active` boolean, and `nowMs` as the memory store. `upsert`, `recordTransaction`, and `deleteByKey` use the same origin and external id pair as insert; `insertIfNew`, `upsert`, and `deleteByKey` also take an optional revision. `findPublicByPubkey` takes a 64-character hex key. `replacePhotos` takes origin, key, prepared photos, and an optional revision. `findPublicPhoto` takes a SHA-256 hex hash. `recordTransaction` also takes `nowMs`. `refreshActivity` takes `nowMs`. `list` takes a positive limit and an optional filter object; `listAll` takes no arguments. Predicates are AND and apply before sort and limit. A blockchain or asset filter uses the tech provider offer, the same rule as the memory store. SQLite binds every value. `filters` takes an optional blockchain. `getById` and `deleteById` take the internal id and do not trim it.
- **Returns / side effects:** Opens the file, enables foreign keys, applies the schema, and implements `MapPlaceStore`. `replaceById` returns `updated`, `missing`, `conflict`, or `keyConflict` (including 409 `Place name belongs to another place`); all but `updated` leave every row, support row, and reservation unchanged. `getById` returns one copy or undefined. `deleteById` is true only when it removed the row. `recordTransaction` uses the same last-instant and payment-day rules as the memory store. A parseable instant deletes stored payment days older than the 7-date window start of `nowMs` before classifying, stores its UTC date only when that date is inside that window, then stores `activity` and `activity_until` from `placeActivity`. An unparseable `occurredAt` does not change the row. A written instant is `new Date(newMs).toISOString()`. `refreshActivity` updates only rows whose stored `activity_until` is non-null and due. `list` returns public rows (`COMPLETE_PLACE_SQL` and `active` = 1); `listAll` returns every row, including inactive and incomplete rows, newest first and without a limit. Neither calls `refreshActivity` or joins payment days. Present filter fields are AND-ed before the sort and the limit, including `shop_type = ?`. Support rows and photos for lists are loaded in chunks of at most 500 place ids. Deleting a pin deletes its support rows, payment days, and photo rows, then every `map_photo` row no `map_place_photo` row uses. The process calls `refreshActivity(Date.now())` at startup and every 1000 ms. `close` closes the handle.
- **Used by:** The process entrypoint. The HTTP end-to-end run exercises it.

## Function: mapRoutes

GET `/filters` returns `{ shopTypes, shopNames, countries, blockchains, assets, activities, techProviders }`. An own property `id` on POST, PUT, or DELETE `/places` is 400 `{ error: "Place field is not allowed: id" }` and writes nothing; on PUT `/places/photos` it is 400 `{ error: "Photo upload field is not allowed: id" }`. GET `/places/:id` returns 200 `{ place }` with `photos`, 301 from the hex key of a public shop to the npub, 404 `{ error: "Place not found" }` when the shop is missing, incomplete, or inactive (the hex key of an inactive shop is 404, not 301), or 503 `{ error: "Places are unavailable" }`. GET `/photos/:file` returns the file, 404 `{ error: "Photo not found" }`, or 503. POST `/places/transactions` returns 200 `{ activity }` from the stored row or 404 `{ error: "Place not found" }` and does not call BTC Map.

## Function: parseAdminPublicKeys

- **Purpose:** Parse `OCP_ADMIN_PUBLIC_KEYS` into the devices allowed to call `/admin`. The value is split on `\n` or `\r\n`. A blank line is skipped. A line whose first non-whitespace character is `#` is a comment and is skipped. Every other line is three fields: `ed25519`, the base64 of the raw 32-byte public key, and a name, or `ssh-ed25519`, the base64 of the OpenSSH wire blob, and a name. The wire blob is a uint32 length, the text `ssh-ed25519`, a uint32 length, and the 32-byte key, and nothing after that. The name matches `^[A-Za-z0-9._@-]{1,64}$` and is unique. Base64 may be padded or unpadded.
- **Inputs:** The environment string. Line numbers are 1-based and count every line, including blanks and comments.
- **Returns / side effects:** The keys in file order. Empty when every line is blank or a comment. A bad line throws `OCP_ADMIN_PUBLIC_KEYS line <N>: malformed key`. A repeated name throws `OCP_ADMIN_PUBLIC_KEYS line <N>: duplicate key name`. The same key material under a second name throws `OCP_ADMIN_PUBLIC_KEYS line <N>: duplicate key`, because the replay key is the key name plus the nonce. Nothing is returned when it throws. No I/O.
- **Used by:** The process entrypoint before it listens.

## Function: decodeBase64

- **Purpose:** Decode strict standard base64. Padded and unpadded input is accepted. A bad alphabet, a length of 4n+1, or padding that does not match the body is rejected.
- **Inputs:** One base64 token.
- **Returns / side effects:** Decoded bytes, or undefined when the token is invalid. No I/O.
- **Used by:** `parseAdminPublicKeys` for public keys and `verifyAdminRequest` for signatures.

## Function: canonicalString

- **Purpose:** Build the UTF-8 string an admin signature covers. The fields are `OCP-ADMIN-v1`, the method in upper case, the host, the path plus the query as given (the server passes the pathname plus search of the parsed request URL, so a lone trailing `?` is dropped), the decimal unix timestamp, the nonce, and the lowercase hex SHA-256 of the raw body. An empty body hashes as zero bytes (`e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`). The fields are joined with `\n`. There is no trailing newline. The key name is not a field.
- **Inputs:** Method, host, path with query, unix seconds, the nonce (16 to 64 characters of `[A-Za-z0-9_-]`), and the raw body bytes.
- **Returns / side effects:** The string the device signs and the server rebuilds. Throws `Admin timestamp must be an integer` when the timestamp is not a safe integer. Throws `Admin nonce is invalid` when the nonce does not match. No I/O.
- **Used by:** `signAdminRequest` and `verifyAdminRequest`.

## Function: signAdminRequest

- **Purpose:** Sign one admin request with an Ed25519 private key. The host is the name the server was configured with, not a header the client picked. The signature is standard base64 of the 64-byte signature over the UTF-8 canonical string. The key name is sent as `OCP-Admin-Key` and is not part of that string. The nonce is part of the signed string and is sent as `OCP-Admin-Nonce`. When the nonce is omitted, 16 random bytes are generated as base64url.
- **Inputs:** Method, host, path with query, unix seconds, raw body, PKCS8 Ed25519 private key, key name, and an optional nonce.
- **Returns / side effects:** The headers `OCP-Admin-Key`, `OCP-Admin-Timestamp` (the decimal timestamp), `OCP-Admin-Signature`, and `OCP-Admin-Nonce`. Throws `Admin timestamp must be an integer` when the timestamp is not a safe integer. Throws `Admin nonce is invalid` when a given nonce does not match. Does not record a replay. No other I/O.
- **Used by:** A device that calls `/admin`. `scripts/ocp-admin.mjs` builds the same four headers. The server checks them with `verifyAdminRequest`.

## Function: verifyAdminRequest

- **Purpose:** Accept one admin request only when the nonce matches, the key name is known, the timestamp header is an integer within 60 seconds of the server clock (the difference may be 60 and must not be 61), and the signature verifies over `canonicalString` for the configured host, the method, the path plus query, the nonce, and the raw body. A missing or malformed nonce returns false before any signature work. A nonce already stored for that key is rejected. Expired entries (expiry strictly before the current unix second) are removed at the start of every call. The replay key is `<keyName>\n<nonce>`, not the signature. On success that key is stored until `timestamp + 60`. Every failure returns false and does not store the nonce. The host argument is the server config, never the request `Host` header.
- **Inputs:** Allowed keys, the header values including the nonce, method, host, path with query, raw body, current unix seconds, and the process replay map.
- **Returns / side effects:** True only when the request is fresh, signed by an allowed key, and not a replay. False for a missing or malformed nonce, a missing or unknown key, a timestamp that is not an integer, a timestamp outside the 60-second window, a bad or wrong-length signature, a signature that does not verify, or a reused nonce. Does not throw. Updates the replay map only after a successful check.
- **Used by:** `adminRoutes` on every `/admin` request once admin is configured.

## Function: adminRoutes

- **Purpose:** Signed maintenance of pins for any origin, mounted at `/admin`. When no key is loaded or the host is blank, every request returns 503 `{ error: "Admin is not configured" }` and the body is not checked. Otherwise a body above 64 KiB returns 413 `{ error: "Payload too large" }` before the signature is checked. Exactly `PUT /admin/places/photos` instead takes the 15 MiB photo limit, and before reading that body it returns 401 `{ error: "Unauthorized" }` unless `OCP-Admin-Key` names a configured key and `OCP-Admin-Timestamp` is an integer within 60 seconds of the clock. The raw body is read once, `verifyAdminRequest` runs against the trimmed configured host and the path plus query of the request URL, and a failure returns 401 `{ error: "Unauthorized" }`. `GET /places` lists every stored pin, including incomplete rows, newest first. Each item is the public place, with `id` set to the internal id that admin writes address and `npub` set to the public id (the npub, or null without a key), plus `complete` and `problems` from one `placeProblems` call, plus `externalId` (the stored caller id), `paymentMethods` (the stored string or null), `createdAt` (the stored string), `lastTransactionAt` (the stored string or null), and `active` (the stored boolean). `complete` and `problems` ignore `active`. `toPublicMapPlace` does not copy `active` and still omits the other admin-only fields. The response does not add `activityUntil` or payment days. `PUT /places` and `DELETE /places` parse those same bytes as JSON (empty or invalid JSON is null). A JSON object with an own property `id` is handled here and does not call `putPlace`, `deletePlace`, `normalizeMapPlaceKey`, or `pushMapPlace`. A non-string `id`, or a string whose trim is empty, is 400 `{ error: "Place id is required" }`, an `id` that starts with `npub1` is 400 `{ error: "Place id is the internal id, not the npub" }`, and a `revision` beside an `id` is 400 `{ error: "Place field is not allowed: revision" }`; each writes nothing. An internal-id write is an admin correction outside the source's write order: it neither checks nor stores a revision (R8). The id is not trimmed before lookup. On PUT, lookup runs before origin, external id, timestamps, activity, `active`, and content checks. An unknown id is 404 `{ error: "Place not found" }`, inserts nothing, and does not call BTC Map, even when fields checked after the lookup are invalid; the npub-id and `revision` 400s come before it. A present origin is normalized first. A failure returns that error and writes nothing. A different valid origin is allowed. A present external id is checked only after origin. A failure returns that error and writes nothing. A different valid caller id is allowed. Omitted origin or external id keep the stored values. A present `createdAt` must be a string whose `Date.parse` is finite and whose `new Date(ms).toISOString()` matches `/^\d{4}-/`. The stored value is that canonical ISO. Otherwise the error is `Place created time is invalid`. Null, numbers, and blank strings are invalid. Omitted `createdAt` keeps the stored value. A present `lastTransactionAt` of JSON null clears it. A string uses the same canonical-ISO rule. Anything else is `Place transaction time is invalid`. Omitted keeps the stored value. A present older instant is still written. This path does not call `recordTransaction`. A present `activity` must be exactly `daily`, `within7Days`, `within30Days`, `olderThan30Days`, or `none`, with no trim. Otherwise the error is `Place activity is invalid`. A present `active` must be a JSON boolean: `true` stores shown and `false` stores hidden. Anything else, including `0`, `1`, `"true"`, `"false"`, and `null`, is `Place active is invalid` and writes nothing. Omitted `active` keeps the stored flag. The check sits with `createdAt`, `lastTransactionAt`, and `activity`. The content is `normalizeMapPlace` on a copy that drops `id`, `createdAt`, `lastTransactionAt`, `activity`, and `active`, then sets the resolved origin and caller id. Those names are not allowed place keys. Any other unknown key, including `activityUntil`, is `Place field is not allowed`. Omitted `supports` becomes `[]`. Omitted `paymentMethods` becomes null. Omitted `techProvider` is stored as `DFX.swiss`. An omitted `nostrPubkey` keeps the stored key (a row without one then fails `Place NOSTR public key is required`); a sent key follows R7 against the resolved pair, and the row's key reservation moves with it. This is a full replace of the operator columns, not a patch, except that a body without the `googleMapsUrl` key keeps the stored Google Maps link. Success calls `replaceById` and does not call `upsert` or BTC Map. `replaceById` receives `set` when `activity` was present, `recompute` when `activity` was absent and `lastTransactionAt` was present (including null), and `keep` when both were absent. `nowMs` is the admin route clock. `keep` leaves activity, the refresh deadline, and payment days. `set` stores that token and clears the refresh deadline so a later refresh does not overwrite it, and leaves payment days. `recompute` classifies from the written instant and the existing payment days. The internal id is not a writable column and a second row is never created. On DELETE, after the same npub-id and `revision` checks, an unknown id is 200 `{ deleted: false }` even when origin or external id is also present, and nothing is inserted. A known id still checks a present origin, then a present external id. A normalizer failure deletes nothing. A normalized value that differs from the stored row is 400 `{ error: "Place origin does not match" }` or `{ error: "Place external id does not match" }` and deletes nothing. A different origin on DELETE is not a rename. Those mismatch errors are unchanged. Success is 200 `{ deleted: true }` via `deleteById`, which removes the row's photos too. Without an own property `id`, PUT calls `putPlace` and DELETE calls `deletePlace`. The request `Host` header is not the signed host.
- **Inputs:** Store, environment, fetch, the allowed keys, the configured host, `publicBaseUrl` for photo URLs in the list, and an optional clock in milliseconds (default `Date.now`). One replay map lives for the life of the app.
- **Returns / side effects:** A Hono app. GET returns 200 `{ places }`. Each place includes `npub`, `externalId`, `paymentMethods`, `createdAt`, `lastTransactionAt`, and `active`, and its `id` is the internal id. PUT without `id` returns the status and body of `putPlace`, including a BTC Map call only when that upsert inserts. PUT with a known `id` returns 200 `{ created: false, id, npub, btcmap: "skipped" }` for that same internal id and does not call `upsert` or BTC Map. PUT with an unknown `id` returns 404 `{ error: "Place not found" }`. A missing row from `replaceById` is the same 404. PUT whose new origin and caller id are already stored on a different row returns 409 `{ error: "Place already exists" }` and changes neither row. A key refused by R7 returns 409 `{ error: "nostrPubkey of a place cannot change" }` or `{ error: "nostrPubkey belongs to another place" }` and writes nothing. A name another row already stores returns 409 `{ error: "Place name belongs to another place" }` and writes nothing. The row's own name is allowed. DELETE without `id` returns the status and body of `deletePlace`. DELETE with `id` returns 200 `{ deleted: true }` or `{ deleted: false }`, or 400 when the id is blank or an npub, a `revision` is sent, a present origin or external id fails its normalizer, or the normalized value does not name that row (`Place origin does not match`, `Place external id does not match`). A different origin on DELETE is not a rename. `PUT /places/photos` returns the status and body of `replacePlacePhotos`: 200 `{ photos, skipped }`, 400, 404 `{ error: "Place not found" }`, or 409 `{ error: "Stale revision" }`, and 401 before the body is read when its key or timestamp header fails the header check. A valid signature for an unknown path falls through as 404. No second database.
- **Used by:** `createApp`, mounted at `/admin`.

## Function: putPlace

- **Purpose:** Full replace of one map pin, or insert it when the origin and external id are new. A body without the `googleMapsUrl` key keeps the stored Google Maps link. Validation, the store write, and the BTC Map call are the same as `PUT /map/places`, including the key rules (R7) and the revision (R8). An own property `id` is `Place field is not allowed: id` and nothing is written. A new row is posted to BTC Map only when this call inserts it. An update does not call BTC Map. A rejected body leaves the stored pin unchanged. This function does not check the ingest bearer or the admin signature. `PUT /admin/places` calls this only when the body has no own property `id`; an internal-id replace stays in `adminRoutes`.
- **Inputs:** Store, BTC Map environment, fetch, and the request JSON. Null, an array, and a non-object are invalid.
- **Returns / side effects:** 400 `{ error }` with the validator message, 409 `{ error }` with `Stale revision`, `nostrPubkey of a place cannot change`, `nostrPubkey belongs to another place`, or `Place name belongs to another place` (nothing stored), 201 `{ created: true, id, btcmap }` when the row is new, or 200 `{ created: false, id, btcmap }` when the pair already existed. `id` is the npub of the key the body carries. `btcmap` is `sent`, `failed`, or `skipped`.
- **Used by:** `mapRoutes` on `PUT /map/places` after the ingest check, and `adminRoutes` on `PUT /admin/places` after the signature check when the body has no own property `id`.

## Function: deletePlace

- **Purpose:** Remove one map pin by origin and external id. Validation is `normalizeMapPlaceDelete`: exactly `origin`, `externalId`, and an optional `revision`, so an own property `id` is `Place field is not allowed: id` and nothing is deleted. A sent revision passes the revision rule (R8) and is stored whether or not a row matched, so a missing pair is still 200 with `{ deleted: false }` and the next write of that pair must send a higher revision. Removing a row keeps the pair's key reservations and stored revision. This call does not contact BTC Map. This function does not check the ingest bearer or the admin signature. `DELETE /admin/places` calls this only when the body has no own property `id`; an internal-id delete stays in `adminRoutes`.
- **Inputs:** Store, and the request JSON. Null, an array, and a non-object are invalid. Required fields are `origin` and `externalId`; `revision` is optional.
- **Returns / side effects:** 400 `{ error }` with the validator message, 409 `{ error: "Stale revision" }`, or 200 `{ deleted: true }` or `{ deleted: false }`. A true result means a row was removed.
- **Used by:** `mapRoutes` on `DELETE /map/places` after the ingest check, and `adminRoutes` on `DELETE /admin/places` after the signature check when the body has no own property `id`.

## Function: replacePlacePhotos

- **Purpose:** Replace every photo of one shop. Validation is `normalizePhotoUpload`; each photo goes through `preparePhoto`, a photo that breaks a rule is skipped and reported with its 0-based index, and the others are stored in their order through `replacePhotos`, with the revision rule (R8). This function does not check the ingest bearer or the admin signature.
- **Inputs:** Store, the public base URL of photo URLs, and the request JSON. Null, an array, and a non-object are invalid.
- **Returns / side effects:** 400 `{ error }` with the `normalizePhotoUpload` message, 404 `{ error: "Place not found" }`, 409 `{ error: "Stale revision" }` (nothing stored on these), or 200 `{ photos, skipped }` with every stored photo as `publicPhoto` and the skipped ones as `{ index, error }`.
- **Used by:** `mapRoutes` on `PUT /map/places/photos` after the ingest check, and `adminRoutes` on `PUT /admin/places/photos` after the signature check.

## Function: stripPhotoMetadata

- **Purpose:** Remove metadata from a shop photo by allow-list, at byte level, and read its displayed size. Nothing is decoded or re-encoded. JPEG keeps the first `APP0` that is a plain JFIF header, rewritten with a 0×0 thumbnail, and the first `APP14` that starts with `Adobe` and has at least 12 bytes (cut to those 12), drops every other `APPn` (EXIF, XMP, MPF, ICC, maker data) and every `COM`, writes back a minimal `APP1` EXIF with only the orientation when the original held 2 to 8, keeps the image markers (`SOFn`, `DHT`, `DAC`, `DQT`, `DRI`, `SOS` with the entropy-coded data of every scan, where fill bytes before an `RSTn` or a stuffed zero are written as one `FF`), drops every other marker (`JPG`, `JPGn`, `DHP`, `EXP`, reserved, and `TEM` or `RSTn` outside a scan), and cuts every byte after the main image's `EOI`. PNG keeps `IHDR`, `PLTE`, `IDAT`, `IEND`, `tRNS`, `gAMA`, `cHRM`, `sRGB`, `cICP`, `sBIT`, `pHYs` and `bKGD`, rebuilds each with a fresh CRC, drops a fixed-size chunk of another length (`gAMA` 4, `cHRM` 32, `sRGB` 1, `cICP` 4, `pHYs` 9), an `sBIT`, `bKGD` or `tRNS` whose length does not fit the colour type, an indexed `bKGD` that names no palette entry, an indexed `tRNS` longer than the palette and a `PLTE` of a non-indexed image, keeps each of the listed ancillary chunks and `PLTE` at most once and only before the first `IDAT`, drops every other chunk (text, EXIF, ICC, time and the rest), writes `IEND` empty and cuts after it. WebP keeps `VP8X` as the first chunk, one `ALPH` after it and before a `VP8 ` frame, and the first `VP8 ` or `VP8L` frame, rebuilds each from its declared size with a zero pad byte, keeps only the alpha flag of `VP8X` with its reserved bytes zeroed, rewrites the RIFF size and cuts after the RIFF end; the size it returns for a WebP is always the frame's, because a `VP8X` canvas must equal the frame size. Bytes inside a kept segment, such as DQT or DHT tables, are copied as they are.
- **Inputs:** The type read from the magic bytes and the decoded file.
- **Returns / side effects:** `{ ok: true, bytes, width, height }`, where a JPEG with orientation 5 to 8 has width and height swapped; `{ ok: false, error: "unreadable" }` when markers or chunks do not walk cleanly to the end (a segment or chunk past the file end, no `EOI`, no `IEND`, no `IDAT` before `IEND`, no `SOF` or frame, no `SOS` whose entropy-coded data ends at a marker, an `SOI` anywhere but at the start, a second `SOF` or a `DNL` anywhere (so the size read from the only frame header is the size that is served; a `DNL` could set another number of lines), a `SOF` under 8 bytes, `IHDR` not first, repeated or not 13 bytes, a `PLTE` that is not 1 to 256 entries of 3 bytes, a `PLTE` of an indexed image with more entries than the bit depth allows (for other colour types such a `PLTE` is dropped), a `DRI` that is not 4 bytes or a `DAC` of odd length, a `VP8X` that is not the first chunk or not exactly 10 bytes, a `VP8 ` frame without its start code or a `VP8L` frame without its signature, a `VP8X` canvas whose width or height differs from the kept frame's, a WebP chunk past the RIFF end); `{ ok: false, error: "animated" }` for a PNG with `acTL` or a WebP with `ANIM`, `ANMF` or the `VP8X` animation flag. No I/O.
- **Used by:** `preparePhoto`.

## Function: photoTypeOf

- **Purpose:** Name the file type from the magic bytes: `FF D8 FF` is JPEG, the PNG signature is PNG, `RIFF`…`WEBP` is WebP.
- **Inputs:** The decoded file.
- **Returns / side effects:** `image/jpeg`, `image/png`, `image/webp`, or null. No I/O.
- **Used by:** `preparePhoto`, which requires it to equal the sent `contentType`.

## Function: photoExtension

- **Purpose:** File extension of a stored photo type in `/map/photos/{sha256}.{ext}`, so each file has exactly one URL.
- **Inputs:** A stored content type.
- **Returns / side effects:** `jpg`, `png`, or `webp`. No I/O.
- **Used by:** `publicPhoto` (and through it `toPublicMapPlace`, `toPublicMapPlaceDetail` and `replacePlacePhotos` on `PUT /map/places/photos` and `PUT /admin/places/photos`), and `mapRoutes` on `GET /map/photos/:file`.

## Function: normalizePhotoUpload

- **Purpose:** Validate the envelope of a `PUT /map/places/photos` body. Allowed top-level keys are exactly `origin`, `nostrPubkey`, `revision`, and `photos`; allowed photo keys are `contentType`, `data`, and `caption`. A malformed envelope is rejected as a whole and nothing is stored.
- **Inputs:** Unknown JSON.
- **Returns / side effects:** `{ ok: true, value: { origin, nostrPubkey, revision, photos } }` or `{ ok: false, error }` with `Photo upload is invalid` (not an object), `Photo upload field is not allowed: <key>`, `Place origin is invalid`, `Place NOSTR public key is invalid` (missing or not `isNostrPubkey`), `Place revision is invalid`, `Photos must be a list of at most 10`, `Photo entry must be an object`, or `Photo field is not allowed: <key>`. In both "not allowed" texts `<key>` is the first unknown key cut to its first 40 characters. No I/O.
- **Used by:** `replacePlacePhotos`, which `mapRoutes` runs on `PUT /map/places/photos` and `adminRoutes` on `PUT /admin/places/photos`.

## Function: preparePhoto

- **Purpose:** Check one photo, remove its metadata with `stripPhotoMetadata`, and hash the stripped bytes. `contentType` must be `image/jpeg`, `image/png`, or `image/webp`; `data` strict base64 of at most 1 048 576 decoded bytes; the magic bytes must equal `contentType`; width and height must be 1 to 4096 (a JPEG with a `DNL` is `could not be read`, so its height is always the `SOF`'s), and for a WebP the checked size is the frame's (a `VP8X` canvas of another size is `could not be read`, so a small canvas cannot hide an oversized frame); the stored file after metadata removal must also be at most 1 048 576 bytes; `caption` is optional, 1 to 200 characters without control characters.
- **Inputs:** One photo entry from `normalizePhotoUpload` and its 0-based index.
- **Returns / side effects:** `{ ok: true, photo: { sha256, contentType, width, height, data, caption } }`, with `caption` null when unset and `sha256` over the stripped bytes, or `{ ok: false, error }` with a sentence that numbers the photo from 1: `Photo N is not a JPEG, PNG or WebP image`, `is not valid base64`, `is larger than 1 MiB`, `caption is invalid`, `does not match its content type`, `is animated`, `could not be read`, or `must be 1 to 4096 pixels wide and high`. No I/O.
- **Used by:** `replacePlacePhotos` on `PUT /map/places/photos` and `PUT /admin/places/photos`; a failing photo is reported in `skipped` and the others are stored.

## Function: parsePublicBaseUrl

- **Purpose:** Validate `OCP_PUBLIC_BASE_URL`: an `https://` origin without path, query, credentials, or trailing slash, in lowercase as `URL.origin` writes it.
- **Inputs:** The environment value.
- **Returns / side effects:** The origin, or null. No I/O.
- **Used by:** The process entrypoint, which refuses to start on null and passes the origin to `createApp`.

## Function: publicPhoto

- **Purpose:** Turn a stored photo reference into the public form, so every answer builds photo URLs the same way: `url` is `<OCP_PUBLIC_BASE_URL>/map/photos/{sha256}.{jpg|png|webp}`, never built from the request's `Host` header.
- **Inputs:** A stored photo and `OCP_PUBLIC_BASE_URL`.
- **Returns / side effects:** `{ url, width, height, caption }`, `caption` null when unset. No I/O.
- **Used by:** `toPublicMapPlace` (cover), `toPublicMapPlaceDetail`, and `replacePlacePhotos` on `PUT /map/places/photos` and `PUT /admin/places/photos`.

## Function: toPublicMapPlaceDetail

- **Purpose:** One shop for `GET /map/places/{npub}`: the `toPublicMapPlace` entry, including `googleMapsUrl`, plus `photos`, every stored photo in display order as `{ url, width, height, caption }` with an absolute `url` from the base URL and `caption` null when unset.
- **Inputs:** A complete stored pin and `OCP_PUBLIC_BASE_URL`.
- **Returns / side effects:** The detail object. No I/O.
- **Used by:** `mapRoutes` on `GET /map/places/:id`.

## Function: placeProblems

- **Purpose:** List why a stored pin is incomplete. This is the completeness rule of `MemoryMapPlaceStore` and the source of `complete` and `problems` on `GET /admin/places`. `SqliteMapPlaceStore` applies the same rule in SQL (`COMPLETE_PLACE_SQL`). The public list uses `PUBLIC_PLACE_SQL`, which is that predicate and `active` = 1. `active` is not part of completeness and there is no problem text for it. `placeProblems` does not mention `active` and does not mention the Google Maps link. A row is complete when name, description, street, house number, postal code, city, and country are non-empty, shop type is `SPAR` or `Others`, a NOSTR key is stored, and `lastTransactionAt` is null or starts with a four-digit year and `Number.isFinite(Date.parse(...))`, which matches what SQLite `julianday` reads for the canonical ISO instants this service writes. The messages, in that order, are `name is empty`, `description is empty`, `street is empty`, `houseNumber is empty`, `postalCode is empty`, `city is empty`, `country is empty`, `shopType must be SPAR or Others`, `lastTransactionAt is not a valid instant`, and `nostrPubkey is missing`. Only the failures are included.
- **Inputs:** A stored pin, including an incomplete row.
- **Returns / side effects:** The problem strings in check order, or `[]` when the pin is complete. No I/O. A pin is complete when this list is empty. The public list also requires `active` = 1.
- **Used by:** `MemoryMapPlaceStore` completeness check, and `adminRoutes` on `GET /admin/places`.
