# Endpoints

## Endpoint: GET /

- **Purpose:** Welcome page for a browser that opens the API host. It names the service and links the public place list, the filter list, the health check, and the website. The page is static and is not a data API.
- **Errors:** No error body. A method other than GET is not this page.
- **Used by:** A person who opens the API host in a browser.
- **Auth:** none.

## Endpoint: GET /healthz

- **Purpose:** Process health for the map API. Returns `{ ok: true }`.
- **Errors:** No error body. The process is up when this answers 200.
- **Used by:** The container health check and deploy checks.
- **Auth:** none.

## Endpoint: GET /map/places

- **Purpose:** Public map list of pins that are complete and whose `active` is 1, newest first. Inactive rows are omitted. The public JSON has no `active` field. Each item is `id`, `origin`, `name`, `description`, `lat`, `lon`, `category`, `techProvider`, `shopType`, `shopName`, `street`, `houseNumber`, `postalCode`, `city`, `country`, `supports`, `activity`, and `coverPhoto`. `id` is the shop's npub (NIP-19 form of its NOSTR key); the internal id is not returned. `coverPhoto` is the first photo as `{ url, width, height }`, or null; `url` is absolute from `OCP_PUBLIC_BASE_URL`. A row is complete when name, description, shop type (`SPAR` or `Others`), street, house number, postal code, city, and country are non-empty, a NOSTR key is stored (R7), and `last_transaction_at` is null or parseable; incomplete or inactive stored rows are omitted, so a shop without a key, or a complete shop with `active` 0, is not listed. `shopType` is the stored enum. `shopName` is deprecated for one release and is `'SPAR'` when `shopType` is `'SPAR'`, otherwise null; it is removed in the release after the rollout. Address parts are required strings on a public row. `supports` is the stored blockchain and asset pairs, sorted. `activity` is the stored token copied on read: `daily` when at least five distinct stored UTC dates lie on the UTC date of the maintenance clock or on one of the previous six UTC dates, `within7Days` when the stored instant is at most 7×24h before the maintenance clock (exactly 7 days stays in this bucket; a future instant is `within7Days`) and the row is not `daily`, `within30Days` when it is older than 7×24h and at most 30×24h (exactly 30 days stays in this bucket), `olderThan30Days` when it is older than 30×24h (one millisecond past 30×24h is `olderThan30Days`, not `none`), or `none` when there is no stored instant or the instant is unparseable and the row is not `daily`. A read copies the stored token and does not reclassify. Maintenance runs on the transaction write and when `activity_until` is due. The process does that maintenance at startup and every 1000 ms. The caller id and payment methods are not included. Omitted `origin` is every public pin. A present `origin` must be the same token as a stored origin. Optional `country`, `shopType` (`SPAR` or `Others`), deprecated `shopName` (`SPAR` or `others`, mapped onto `shopType` for one release), `blockchain`, and `asset` further restrict the store read. If `shopType` and `shopName` are both present and map to different types, the request is 400. All predicates are AND and run before `limit`. No stored field is derived from another field; the response field `shopName` is a read-only alias of `shopType` kept for one release. Filters do not read the street, house number, postal code, or city columns. A pin that already has support rows matches only those rows. A pin with none matches the hardcoded payment-link catalog: origin `21gifts` or tech provider `21.gifts` matches Lightning and BTC only, and every other pin matches a catalog network, asset, or pair.
- **Errors:** 400 `{ error: "Invalid limit" }` when `limit` is not an integer from 1 to 1000. Omitted `limit` means 1000. 400 `{ error: "Place origin is invalid" }` when `origin` is present but not a valid origin token. 400 `{ error: "Place country is invalid" }` when `country` is present but not an assigned ISO 3166-1 alpha-2 DFX country symbol. 400 `{ error: "Place shop type is invalid" }` when `shopType` is present and not `SPAR` or `Others`, or when `shopType` and `shopName` map to different types. 400 `{ error: "Place shop name is invalid" }` when the deprecated `shopName` query is present and not `SPAR` or `others`. 400 `{ error: "Place support is invalid" }` when `blockchain` is present but not a payment-link or stored payment-network name, or when `asset` is present but not a ticker, a prefixed ticker, or a payment-link catalog name.
- **Used by:** The OpenCryptoPay map.
- **Auth:** none. Browser calls are allowed from any origin.

## Endpoint: GET /map/filters

- **Purpose:** Public list of filter values for the map. `shopTypes` is always exactly `["SPAR", "Others"]`. `shopNames` is the deprecated one-release alias `["SPAR", "others"]` and is removed in the release after the rollout. `countries` are the distinct ISO country codes of public rows only (complete and `active` is 1), sorted. A country whose only public shop is deactivated drops out. Incomplete stored rows, including rows without a NOSTR key, and inactive rows do not contribute a country. `blockchains` and `assets` are the hardcoded payment-link catalog plus distinct stored values from every row, including inactive and incomplete rows, sorted. `?blockchain=` limits the top-level `assets` to that chain and still returns every blockchain. `activities` is always `daily`, `within7Days`, `within30Days`, `olderThan30Days`, `none`, in that order, and is not narrowed by `?blockchain=`. `techProviders` lists the full hardcoded offer for `DFX.swiss` and for `21.gifts` (Lightning and BTC only) and is not narrowed by `?blockchain=`.
- **Errors:** 400 `{ error: "Place support is invalid" }` when `blockchain` is present but not a payment-link or stored payment-network name.
- **Used by:** The OpenCryptoPay map filter UI.
- **Auth:** none. Browser calls are allowed from any origin.

## Endpoint: GET /map/places/:id

- **Purpose:** One shop of the public list by its NOSTR identity (R7). `:id` is the shop's npub; the response is `{ place }` with the same fields as a `GET /map/places` item plus `photos`, every photo in display order as `{ url, width, height, caption }` with `caption` null when unset. The 64 lowercase hex form of the key of such a shop answers 301 with `Location: /map/places/{npub}`. The hex form of an inactive shop is 404, not 301.
- **Errors:** 404 `{ error: "Place not found" }` for anything else, including an unknown key, a shop that is stored but not complete, a stored shop that is inactive, a wrong npub checksum, and uppercase hex. 503 `{ error: "Places are unavailable" }` when the store read fails. `Cache-Control: public, max-age=60` on 200, 301, and 404; `Cache-Control: no-store` on 503.
- **Used by:** The shop page on opencryptopay.io and any client that links to one shop.
- **Auth:** none. Browser calls are allowed from any origin.

## Endpoint: POST /map/places

- **Purpose:** Create one complete map pin. Allowed JSON keys are exactly origin, externalId, name, description, lat, lon, category, paymentMethods, techProvider, shopType, street, houseNumber, postalCode, city, country, supports, nostrPubkey, and revision. Any other key, including the old `shopName` and `active`, is rejected and nothing is stored. Name, description, shop type (`SPAR` or `Others`), all five address parts, and coordinates are required. House number is required, trimmed, and must match `^[0-9][0-9A-Za-z/ .&–-]{0,31}$`. No stored field is derived from another field; the response field `shopName` is a read-only alias of `shopType` kept for one release. `nostrPubkey` (R7) is the shop's NIP-01 key, 64 lowercase hex characters on secp256k1, and is required (step 1b): a body without it is 400 `{ error: "Place NOSTR public key is required" }` and nothing is stored. Rows stored before step 1a may still have no key; they are not listed until a write adds one. A key stays reserved for its origin and external id forever, also after delete. `revision` (R8) is an optional integer from 1 to 9007199254740991; once one is stored for the pair, every write must send a higher one. Every accepted write stores its revision, also when it changes nothing. The same `origin` and `externalId` returns the first row, including its tech provider, and does not call BTC Map again; a row without a key stores the key this request carries. The response `id` is the npub of the key the body carries. A new row is posted once when `BTCMAP_ACCESS_TOKEN` is set. An omitted tech provider is stored as `DFX.swiss`. Omitted `supports` is stored as `[]`.
- **Errors:** 503 `{ error: "Place ingest is not configured" }` when the ingest token is unset or blank. 401 `{ error: "Unauthorized" }` when the bearer does not match. 400 with the validator message for a bad body, including `Place field is not allowed: <key>` for the first unknown key in `Object.keys` order, `Place NOSTR public key is required`, `Place NOSTR public key is invalid`, and `Place revision is invalid`. Then 409 `{ error: "Stale revision" }` for a revision that is not higher than the stored one or missing once one is stored, then 409 `{ error: "nostrPubkey of a place cannot change" }` when the stored row has a different key, then 409 `{ error: "nostrPubkey belongs to another place" }` when the key is reserved for another origin or external id. A 409 stores nothing. A BTC Map failure still returns 201 with `btcmap: "failed"`.
- **Used by:** Trusted callers that add a shop the first time it appears.
- **Auth:** `Authorization: Bearer` must equal `OCP_PLACE_INGEST_TOKEN`. Status 201 when new, 200 when the pair already exists.

## Endpoint: PUT /map/places

- **Purpose:** Full replace of one map pin, or create it when the origin and external id are new. Every stored field of the pin is replaced by the body: name, description, lat, lon, category, paymentMethods, techProvider (omitted becomes `DFX.swiss`), shopType, street, houseNumber, postalCode, city, country, and supports (omitted becomes `[]`). Id, createdAt, lastTransactionAt, payment days, activity, the stored `active` flag, and a stored NOSTR key stay, so a source write cannot turn a shop back on; the body must carry `nostrPubkey`; a stored key stays, and a row stored before step 1a without a key stores the key the body carries. The same validation as POST applies, including unknown-key rejection, `nostrPubkey`, and `revision`. The response `id` is the npub of the key the body carries. BTC Map is called only when this request inserts the row. An update returns `btcmap: "skipped"` and does not call BTC Map. A rejected body leaves the stored shop unchanged.
- **Errors:** 503 `{ error: "Place ingest is not configured" }` when the ingest token is unset or blank. 401 `{ error: "Unauthorized" }` when the bearer does not match. 400 with the validator message for a bad body. Then the same three 409 answers as POST, in the same order; a 409 stores nothing.
- **Used by:** Trusted callers that correct a shop or set its tech provider.
- **Auth:** `Authorization: Bearer` must equal `OCP_PLACE_INGEST_TOKEN`. Status 201 when new, 200 when the pair already exists.

## Endpoint: DELETE /map/places

- **Purpose:** Remove one map pin by origin and external id, with its photos; a photo file no other shop uses is deleted. A missing pair returns `{ deleted: false }` with status 200; a revision sent for it is stored too. The pair's key reservations and stored revision stay after the delete, so a late older request cannot bring the shop back and its keys cannot move to another shop. This call does not contact BTC Map.
- **Errors:** 503 `{ error: "Place ingest is not configured" }` when the ingest token is unset or blank. 401 `{ error: "Unauthorized" }` when the bearer does not match. 400 with the validator message for a bad body, including `Place field is not allowed: <key>` for any key other than `origin`, `externalId`, and `revision` (`id` included), and `Place revision is invalid`. 409 `{ error: "Stale revision" }` when a revision is stored for the pair and the body sends none or one that is not higher.
- **Used by:** Trusted callers that take a shop off the public map.
- **Auth:** `Authorization: Bearer` must equal `OCP_PLACE_INGEST_TOKEN`. The JSON body is exactly `origin`, `externalId`, and an optional `revision`.

## Endpoint: PUT /map/places/photos

- **Purpose:** Replace every photo of one shop. The body is `{ origin, nostrPubkey, revision?, photos: [{ contentType, data, caption? }] }`. The shop is the stored place with that key and that origin, listed or not. `photos` is the whole list in display order, at most 10, the first being the cover; an empty list removes every photo. Each photo is checked by `preparePhoto` and stripped of metadata by `stripPhotoMetadata` before it is stored; the stored bytes are the stripped bytes. A photo that breaks a rule is skipped and reported, and the others are stored in their order. `revision` (R8) shares the place's counter with `POST`, `PUT`, and `DELETE /map/places`. Files no shop uses any more are deleted. `PUT /map/places` keeps the photos.
- **Errors:** 503 `{ error: "Place ingest is not configured" }`, then 401 `{ error: "Unauthorized" }`, then 413 `{ error: "Payload too large" }` for a body above 15 MiB, then 400 with the `normalizePhotoUpload` message for a malformed envelope, then 404 `{ error: "Place not found" }` when no stored place of that origin has the key, then 409 `{ error: "Stale revision" }`. Nothing is stored on any of these.
- **Used by:** Sources that show photos of their shops, today 21.gifts.
- **Auth:** `Authorization: Bearer` must equal `OCP_PLACE_INGEST_TOKEN`. The answer is 200 `{ photos: [{ url, width, height, caption }], skipped: [{ index, error }] }` with `index` 0-based and the error sentence numbering photos from 1.

## Endpoint: GET /map/photos/:file

- **Purpose:** Serve one stored photo. `:file` is `{sha256}.{jpg|png|webp}`, the hash of the stripped bytes and the extension of the stored type. The file is served only while a public shop uses it. A deactivated shop does not count; a hash still used by another public shop is served. Photo bytes stay stored. The answer carries the stored type as `Content-Type`, `X-Content-Type-Options: nosniff`, and `Cache-Control: public, max-age=31536000, immutable`; a new photo has a new hash and so a new URL.
- **Errors:** 404 `{ error: "Photo not found" }` with `Cache-Control: no-store` for any other name, a wrong extension, an unknown hash, or a file no listed shop uses. 503 `{ error: "Places are unavailable" }` with `Cache-Control: no-store` when the store read fails.
- **Used by:** The OpenCryptoPay map and shop page through the `url` of `coverPhoto` and `photos`.
- **Auth:** none. Browser calls are allowed from any origin.

## Endpoint: POST /map/places/transactions

- **Purpose:** Record a transaction time on an existing pin. The JSON body is `origin`, `externalId`, and optional `occurredAt`. The response is `{ activity }` copied from the stored row after the write. This call does not create a pin and does not call BTC Map. An older or equal stored instant is kept. A parseable instant deletes stored payment days older than the 7-date window start of the request clock before classifying, stores its UTC date when that date is inside that window, then stores `activity` and `activity_until`. Maintenance also runs when `activity_until` is due. The process does that maintenance at startup and every 1000 ms. Browser CORS `allowMethods` stays `GET` and `OPTIONS`; this call is server-to-server. The write also works on an incomplete stored row; that row stays hidden from GET `/map/places` until it is complete.
- **Errors:** 503 `{ error: "Place ingest is not configured" }` when the ingest token is unset or blank. 401 `{ error: "Unauthorized" }` when the bearer does not match. 400 with the validator message for a bad body, including `Place transaction time is invalid`. 404 `{ error: "Place not found" }` when the pair is missing.
- **Used by:** Trusted callers that report a shop transaction.
- **Auth:** `Authorization: Bearer` must equal `OCP_PLACE_INGEST_TOKEN`. Browser CORS `allowMethods` stays GET and OPTIONS.

## Endpoint: GET /admin/places

- **Purpose:** List every stored pin for maintenance, including rows the public map hides, newest first. Each item is the public place (`origin`, `name`, `description`, `lat`, `lon`, `category`, `techProvider`, `shopType`, `shopName`, `street`, `houseNumber`, `postalCode`, `city`, `country`, `supports`, `activity`, `coverPhoto`) with `id` set to the internal id that admin writes address and `npub` set to the public id (the npub, or null for a row without a NOSTR key), plus `complete`, `problems`, `externalId`, `paymentMethods`, `createdAt`, `lastTransactionAt`, and `active`. `complete` is true when `problems` is empty. `problems` is the `placeProblems` list and ignores `active`. `externalId` is the stored caller id. `paymentMethods` is the stored string or null. `createdAt` is the stored string. `lastTransactionAt` is the stored string or null. `active` is the stored boolean, `true` or `false`, and is not inside the public place object. The response does not include `activityUntil` or payment days. The response is `{ places }`.
- **Errors:** 503 `{ "error": "Admin is not configured" }` when no public key is loaded or `OCP_ADMIN_HOST` is missing or blank. 413 `{ "error": "Payload too large" }` when the body is above 64 KiB; this is checked before the signature. 401 `{ "error": "Unauthorized" }` when `OCP-Admin-Key`, `OCP-Admin-Timestamp`, `OCP-Admin-Nonce`, or `OCP-Admin-Signature` is missing, the nonce is malformed, the key name is unknown, the signature does not verify, the timestamp is not an integer, the timestamp is more than 60 seconds from the server clock, the signed host, method, path, query, or body does not match, or this nonce was already accepted for the key. This route does not return 400.
- **Used by:** `scripts/ocp-admin.mjs list` and an operator checking pins of any origin.
- **Auth:** Ed25519 over the canonical string, not the ingest bearer. Required headers are `OCP-Admin-Key` (the key name), `OCP-Admin-Timestamp` (unix seconds), `OCP-Admin-Nonce` (random, 16 to 64 characters of A-Z a-z 0-9 _ -), and `OCP-Admin-Signature` (standard base64). The signed host is `OCP_ADMIN_HOST`. The request `Host` header is ignored. The signed path and query are the pathname plus search of the parsed request URL, so a lone trailing `?` is dropped. The body is empty and is still hashed.

## Endpoint: PUT /admin/places

- **Purpose:** Full replace of one pin for any origin. When the JSON object has no own property `id`, this creates the pin when the origin and external id are new. That body and its success body are the same as `PUT /map/places`, including `nostrPubkey` and `revision` and the source rules R7 and R8: 201 `{ created: true, id, btcmap }` when the row is new, 200 `{ created: false, id, btcmap }` when it already existed, with `id` the npub. BTC Map is called only on that insert. `id`, `createdAt`, `lastTransactionAt`, `activity`, and `active` are unknown fields on that path and write nothing. When `id` is an own property, it is the internal id from `GET /admin/places` and is not trimmed before lookup. The internal id is the address and is not a writable column. A non-string `id`, a string whose trim is empty, or an npub writes nothing. A `revision` is rejected on this path: an admin correction is outside the source's write order (R8), so it neither checks nor stores a revision. An unknown id inserts nothing and does not call BTC Map. Lookup runs before origin, external id, timestamps, activity, `active`, and content checks. A present `origin` goes through the origin normalizer. A failure returns that error and writes nothing. A different valid origin is allowed. A present `externalId` goes through the external-id normalizer and is checked only after origin. A failure returns that error and writes nothing. A different valid caller id is allowed. Omitted `origin` or `externalId` keep the stored values. A present `createdAt` must be a string whose `Date.parse` is finite and whose `new Date(ms).toISOString()` matches `/^\d{4}-/`. The stored value is that canonical ISO. Otherwise the error is `Place created time is invalid`. Null, numbers, and blank strings are invalid. Omitted `createdAt` keeps the stored value. A present `lastTransactionAt` of JSON null clears it. A string uses the same canonical-ISO rule. Anything else is `Place transaction time is invalid`. Omitted keeps the stored value. A present older instant is still written. This path does not call `recordTransaction`. A present `activity` must be exactly `daily`, `within7Days`, `within30Days`, `olderThan30Days`, or `none`, with no trim. Otherwise the error is `Place activity is invalid`. A present `active` must be a JSON boolean: `true` stores the shop as shown and `false` stores it as hidden. Anything else, including `0`, `1`, `"true"`, `"false"`, and `null`, is `Place active is invalid` and writes nothing. A body whose only own properties are exactly `id` and a JSON boolean `active` does not call `normalizeMapPlace`. It calls `replaceById` with the stored fields, the stored timestamps, activity `keep`, and that boolean. A null key stays null. Success `npub` is null. No other field changes. There is no BTC Map call. Omitted `active` keeps the stored flag. The check sits with `createdAt`, `lastTransactionAt`, and `activity`. The content is validated with `normalizeMapPlace` on a copy that drops `id`, `createdAt`, `lastTransactionAt`, `activity`, and `active`, then sets the resolved origin and caller id. Those names stay off the allowed place keys. Any other unknown key, including `activityUntil`, is rejected and writes nothing. Omitted `supports` becomes `[]`. Omitted `paymentMethods` becomes null. Omitted `techProvider` is stored as `DFX.swiss`. An omitted `nostrPubkey` keeps the stored key; a row without a stored key needs one in the body (400 `Place NOSTR public key is required`). A sent key follows R7 against the resolved pair: it is stored on a row without a key unless it is reserved for another pair, and a stored key cannot change. The row's key reservation moves with the row to the resolved pair. This replaces the operator columns; it is not a patch. A validator failure writes nothing. Success calls `replaceById` and is 200 `{ created: false, id, npub, btcmap: "skipped" }` for that same internal id, with `npub` the npub of the row's key. It does not call `upsert` or BTC Map, and it never inserts a second row. `replaceById` receives `set` when `activity` was present, `recompute` when `activity` was absent and `lastTransactionAt` was present (including null), and `keep` when both were absent. `nowMs` is this route's clock. `keep` leaves activity, the refresh deadline, and payment days. `set` stores that token and clears the refresh deadline so a later refresh does not overwrite it, and leaves payment days. `recompute` classifies from the written instant and the existing payment days, including a null instant: five counted payment days are still `daily`. The bytes that are hashed are the bytes that are parsed.
- **Errors:** 503 `{ "error": "Admin is not configured" }` when no public key is loaded or `OCP_ADMIN_HOST` is missing or blank. 413 `{ "error": "Payload too large" }` when the body is above 64 KiB; this is checked before the signature. 401 `{ "error": "Unauthorized" }` for every signature failure, including a stale timestamp, a replay, a wrong signed host, and a body that is not the signed bytes. When `id` is an own property: 400 `{ "error": "Place id is required" }` when `id` is not a string or its trim is empty; 400 `{ "error": "Place id is the internal id, not the npub" }` when it starts with `npub1`; 400 `{ "error": "Place field is not allowed: revision" }` when the body has a `revision`; 404 `{ "error": "Place not found" }` when that id is missing, even if fields checked after the lookup are invalid (the npub-id and `revision` 400s come before it), and again when `replaceById` reports the row missing; 400 `{ "error": "Place origin is invalid" }` when a present origin fails the origin normalizer; 400 `{ "error": "Place external id is required" }` when a present external id fails the external-id normalizer. Origin is checked before external id. 400 `{ "error": "Place created time is invalid" }` when a present `createdAt` is not a canonical four-digit-year instant. 400 `{ "error": "Place transaction time is invalid" }` when a present `lastTransactionAt` is neither JSON null nor such an instant. 400 `{ "error": "Place activity is invalid" }` when a present `activity` is not an exact token. 400 `{ "error": "Place active is invalid" }` when a present `active` is not a JSON boolean; the stored flag stays. The place validator then returns 400, including `{ "error": "Place must be a latitude and longitude" }` for coordinates that are missing or out of range, `{ "error": "Place field is not allowed: <key>" }` for the first unknown key with `<key>` cut to 40 characters, and `{ "error": "Place name is required" }`, `{ "error": "Place name must not contain the address" }`, `{ "error": "Place category is required" }`, `{ "error": "Place tech provider is invalid" }`, `{ "error": "Place country is invalid" }`, `{ "error": "Place street is invalid" }`, `{ "error": "Place house number is invalid" }`, `{ "error": "Place postal code is invalid" }`, `{ "error": "Place city is invalid" }`, `{ "error": "Place shop type is invalid" }`, `{ "error": "Place description is invalid" }`, `{ "error": "Place support is invalid" }`, `{ "error": "Place NOSTR public key is required" }` (no key in the body and none stored on the row), or `{ "error": "Place NOSTR public key is invalid" }` for the first field that fails. 409 `{ "error": "Place already exists" }` when the resolved origin and caller id already belong to a different row; neither row changes. 409 `{ "error": "nostrPubkey of a place cannot change" }` when the row has a key and the body sends another, and 409 `{ "error": "nostrPubkey belongs to another place" }` when the sent key is reserved for another pair; nothing is written. When `id` is absent, an empty body, invalid JSON, or a non-object is 400 `{ "error": "Place must be a latitude and longitude" }`, and the same validator errors apply, including `Place field is not allowed` for `id`, `createdAt`, `lastTransactionAt`, `activity`, and `active`, `{ "error": "Place NOSTR public key is required" }`, `{ "error": "Place NOSTR public key is invalid" }` and `{ "error": "Place revision is invalid" }`; 409 with the same three texts and order as `PUT /map/places`. A 400, 404, or 409 leaves the stored pins unchanged. `Place origin does not match` and `Place external id does not match` are not PUT errors. They remain DELETE errors.
- **Used by:** `scripts/ocp-admin.mjs put` and an operator correcting a pin.
- **Auth:** The same four headers as `GET /admin/places`. The signature covers this PUT, `OCP_ADMIN_HOST`, the pathname plus search of the parsed request URL (a lone trailing `?` is dropped), the timestamp, the nonce, and the SHA-256 of these raw body bytes. The ingest bearer is not accepted here.

## Endpoint: DELETE /admin/places

- **Purpose:** Remove one pin. When the JSON object has no own property `id`, the body is exactly `origin`, `externalId`, and an optional `revision`, as on `DELETE /map/places`, with the same R8 rule. Status 200 is `{ "deleted": true }` when a row was removed and `{ "deleted": false }` when the pair is missing. When `id` is an own property, it is the internal id from `GET /admin/places` and is not trimmed before lookup. A non-string `id`, a string whose trim is empty, an npub, or a `revision` deletes nothing; this path neither checks nor stores a revision, and the pair's key reservations and revision stay. An unknown id returns 200 `{ "deleted": false }` even if `origin` or `externalId` is also present (the npub-id and `revision` 400s come before the lookup), and inserts nothing. A known id checks a present `origin`, then a present `externalId`, with the same normalizers as `PUT /admin/places`. A normalizer failure returns that error and deletes nothing. A normalized value that differs from the stored row deletes nothing. That mismatch is unchanged: the errors are `Place origin does not match` and `Place external id does not match`, and a different origin is not a rename. Omitted `origin` or `externalId` are allowed. Success is 200 `{ "deleted": true }` and that row only is removed, with its photos; a photo file no other shop uses is deleted. This call does not contact BTC Map.
- **Errors:** 503 `{ "error": "Admin is not configured" }` when no public key is loaded or `OCP_ADMIN_HOST` is missing or blank. 413 `{ "error": "Payload too large" }` when the body is above 64 KiB; this is checked before the signature. 401 `{ "error": "Unauthorized" }` for every signature failure, including a stale timestamp, a replay, a wrong signed host, and a body that is not the signed bytes. When `id` is an own property: 400 `{ "error": "Place id is required" }` when `id` is not a string or its trim is empty; 400 `{ "error": "Place id is the internal id, not the npub" }` when it starts with `npub1`; 400 `{ "error": "Place field is not allowed: revision" }` when the body has a `revision`; 400 `{ "error": "Place origin is invalid" }` or `{ "error": "Place external id is required" }` when a present field fails its normalizer; 400 `{ "error": "Place origin does not match" }` or `{ "error": "Place external id does not match" }` when the normalized value names a different row. Origin is checked before external id. An unknown id is not a 400. When `id` is absent: 400 `{ "error": "Place origin is invalid" }` when the body is empty, invalid JSON, not a JSON object, or the origin is not a valid token, 400 `{ "error": "Place external id is required" }` when `externalId` is missing or invalid, 400 `{ "error": "Place field is not allowed: <key>" }` for any other key, and `{ "error": "Place revision is invalid" }`; 409 `{ "error": "Stale revision" }` as on `DELETE /map/places`. A 400 or 409 deletes nothing.
- **Used by:** `scripts/ocp-admin.mjs delete` (with `--revision` for a place whose source writes with revisions) and an operator taking a pin off the map.
- **Auth:** The same four headers as `GET /admin/places`. The signature covers this DELETE, `OCP_ADMIN_HOST`, the pathname plus search of the parsed request URL (a lone trailing `?` is dropped), the timestamp, the nonce, and the SHA-256 of these raw body bytes. The ingest bearer is not accepted here.
